# VbeComplete — VBA 变量名/过程名自动补全工具

在 VBE（VBA 编辑器）代码窗里输入变量/过程名的首字母（或中文首字），自动弹出候选列表，
`Tab` 确认补全，`↑`/`↓` 选择，`Shift+↑`/`Shift+↓` 跳出列表并把光标上/下移一行，`Esc` 取消；
**鼠标点击其它地方，弹窗会自动消失**。
支持中文命名的变量/常量/过程（如 `Dim 用户名 As String`）。解决 VBE 原生只对"对象.成员"
弹列表、但不对自定变量名弹列表的痛点。

## 技术栈

- **Python** + `pywin32`（驱动 VBA 编辑器 COM）+ `pynput`（全局键盘监听）+ `tkinter`（弹窗）
- 核心解析与补全逻辑是纯 Python，不写任何日志文件、不含测试与调试代码。

## 安装与运行

1. 确保本机已安装 Python 3.8+（建议从 python.org 安装，并勾选"Add to PATH"）。
2. 首次运行会自动 `pip install` 依赖，请**以能联网的普通用户**双击 `run.bat`
   （后台静默运行）。若想看报错，在命令行运行 `python main.py`（带控制台）。
3. 在 Excel 中开启权限（必须）：
   **文件 → 选项 → 信任中心 → 信任中心设置 → 宏设置 →**
   **勾选"信任对 VBA 工程对象模型的访问"**。
4. 打开 VBE（`Alt+F11`），在代码窗输入一个变量名的首字母，即可看到补全列表。

## 使用

### 快捷键一览

| 操作 | 作用 |
| --- | --- |
| 输入字母 / 数字 / `_` | 弹出并实时过滤候选列表 |
| `↑` / `↓` | 上下选择候选（循环）；一屏放不下时自动滚动 |
| `Shift+↑` / `Shift+↓` | **跳出候选列表**，并把光标上/下移一行（v78） |
| `Tab` | 确认补全（唯一确认键） |
| `Esc` | 取消补全 |
| 单击 / 双击候选 | 用鼠标确认 |
| `Ctrl+Space` | 手动强制弹出 |
| `Shift+Enter` | 在当前行下方新起一行（缩进与上一行对齐） |
| `Enter`（行尾） | 正常换行；**整行注释 / 块结构开头会自动缩进**，块头还**自动补收尾**（v79 / v79b） |
| `←` / `→` | 收起列表（按键照常作用于 VBE，光标该移还移） |
| 点击弹窗以外 | 自动收起列表 |

### 功能说明

- **输入即提示，实时过滤**：输入字母/数字/`_` 即弹列表，继续输入会实时过滤。
- **提示只在【代码窗格】里出现**（v64）：VBE 里的**属性窗口、工程窗口、窗体设计器**
  都不是写代码的地方，在那里打字/改属性值时**不会**冒出候选窗。
  判据是"VBE 线程里当前拥有键盘焦点的窗口，父链上有没有**代码窗格**"（窗口类
  `VbaWindow`）—— 比"前台窗口标题里有没有 Microsoft Visual Basic"精确得多，
  后者对上面那些子窗口**一律**返回真，正是"在属性窗口里改属性值时冒出提示"的成因。
  焦点不在代码窗格时：**不弹候选**、并**收起已经挂着的候选窗**，也不会替你做
  自动配对 / `Shift+Enter` 换行（免得把字符写进代码窗格）；`Ctrl+Space` 同样不接管。
  判不出来时（找不到 VBE 主窗口 / 宿主窗口类名不同）退回旧判据，绝不"拿不准就拦"。
  想退回旧行为：`set VBECOMPLETE_NO_CODE_AREA_GATE=1`。
- **模糊匹配：不要求从首字母开始**。只要输入的几个字符**按顺序**出现在名字里就会提示，
  **命中的字符标红**，一眼看出为什么它被匹配到。例如定义了 `dataArr` 和 `dataSheet`：
  - 输入 `ts` → 提示 `dataSheet`（da**t**a**S**heet，`datasheet` 里没有连续的 `ts`，
    所以按**词边界**命中两个 `t`/`S`）；
  - 输入 `ta` → 同时提示 `dataArr` 和 `dataSheet`（两边都是连续的 **ta**）；
  - 输入 `ds` → 提示 `dataSheet`（**D**ata**S**heet，camelCase 词首缩略）；
  - 输入 `arr` → 提示 `dataArr`（data**Arr**，优先命中连续块，而不是散着凑字母）。
  候选按「精确 > 前缀 > 词首缩略 > 连续块 > 分散」排序，同级再比命中是否更靠前、
  跨度是否更小、名字是否更短——最像的永远排第一，列表不会因为放开了模糊匹配就变乱。
  输入普通前缀（如 `num`）时结果与纯前缀匹配完全一致，不会平白多出一堆噪音。
- **只提示「你这个工程里真实存在的东西」**（★v77，用户口径）。候选池就是四类：
  **变量名**（含没写 `Option Explicit` 时"用过即存在"的那种）+ **你自己写的
  `Sub` / `Function` / `Property`** + **组件名**（标准模块 / 窗体 / 类模块）+ **窗体控件名**。
  VBA 语言自带的名字（内建函数、内建数据类型、语言关键字、各种枚举常量）**默认
  全部不提示** —— 用户原话："我觉得提示词太多了……你把提示 vba 本身带的关键字、
  函数这块都删掉吧。保留能提示变量名，自定义的函数/过程名，窗体/控件名，模块名。"
  - 想单独开回来（任一都是 `set VBECOMPLETE_xxx=1`，改完重启生效）：
    - **内建函数 + 内建数据类型**（`MsgBox`、`Left`、`Split`、`String`、`Long` …）：
      `VBECOMPLETE_VBA_BUILTINS=1`；
    - **语言关键字**（`Sub`、`Dim`、`If`、`For`、`Set` …）：`VBECOMPLETE_VBA_KEYWORDS=1`；
    - **VBA 内建枚举常量**（`vbCrLf`、`vbYes`、`vbOK` … 共 102 条）：
      `VBECOMPLETE_VBA_CONSTANTS=1`；
    - **宿主类型库枚举常量**（Excel `xl*` / Office `mso*`，共 4500+ 条）：
      `VBECOMPLETE_HOST_ENUMS=1`（只想留一族：`VBECOMPLETE_HOST_ENUM_FAMILIES=xl`）。
  - ⚠️ 唯一的连带后果：`Dim x As <这里>` **不再补 `Long` / `String` 这类内建类型名**
    （那个位置的候选是"先出候选、再按类型名筛"，不在池子里就永远显示不出来）——
    那一位置现在只剩你自己的类型：窗体 / 类模块 / 模块名 + `Type` / `Enum` 名。
    想要回内建类型：开 `VBECOMPLETE_VBA_BUILTINS=1`。
  - ⚠️ **四份清单一个字都没裁**，只按开关在收集侧取舍 —— 所以"更安静"不是"能力删除"，
    想开回来随时有效（默认值这件事由回归测试第 54 节钉着）。
  - 开回来之后，这些名字代码里 **一个字都没写过**也照样提示 —— 它们由语言运行时决定存在：

  ⚠️ 打开之后这几条的**匹配口径比工程内名字紧**（不紧的话它们会淹掉你自己的名字）——
  第一条（内建名字 + 关键字）在这些开关打开时才生效；第二条（宿主常量）只在把宿主枚举打开后才生效：
  - 内建名字 + 关键字（约 260 个，v71 放宽）：**跳着打的时候，第一个字母必须与
    候选名的首字母相同** —— `ve`→`VarType`、`vr`→`VarType`（都是 v 开头）放行，
    而 `xl`→`Explicit`、`ms`→`Implements`（首字母对不上）挡掉。
    连续 / 前缀 / 词首缩略命中不受此限：`ms`→`MsgBox`、`vt`→`VarType`、
    `slct`→`Select` 照常。想退回 v61~v70 的老口径（2~3 字符只留连续/前缀命中）：
    `set VBECOMPLETE_BUILTIN_SCATTER_MIN=4`；
  - 宿主常量（约 4500 条）：**必须从家族前缀开头**（`xl` / `mso` —— 这条不能松，
    正是它把 `ms` 带出 2365 条 `mso*`、`count` 带出上百条这类噪音整片挡掉的），
    再要求你**打进去过一段连续的名字片段（≥ 4 个字符）**：
    `xl`→`xl*`、`xlu`→`xlUp`、`mso`→`mso*` 照常，`ms` 只出 `MsgBox`（绝不带出
    `mso*`）、`count` / `cell` / `range` 一条 `xl*` 都不会多出来；
    而**跳着打**也能命中（v68）—— `xlworkfaul` → `xlWorkbookDefault`、
    `xlcell` → `xlCellTypeVisible`（前缀）`+ xlLastCell`（跳步，永远排在前缀之后）。
    输入不足 4 个字符时退化成纯前缀，与只认前缀时**一模一样**，不会平白多出噪音。
    （v69 给这一段加了一层廉价的"4 连片断"预筛：候选集一字不变，宿主那段耗时
    约降到三分之一，整条匹配快 1.5~2.8 倍。见"跳着打补不出来"那条。）
- **打全名照样提示**：名字打全了列表不会消失（`Sub tes` → `Sub test` 始终提示 `test`），
  包括**正在写函数/变量声明行**的时候——只要那个名字在工程里真实存在就一直提示。
  真正会被剔掉的只有"幻影词"：工程里哪都不存在、只是你正在敲的那几个字符
  （比如回退删出来的 `numA`），那才叫"提示自己"。
- **从名字的结尾 / 中间 / 开头删字符，都会继续出提示**。
  当前词取的是「**光标所在处那一整个名字**」，而不是"光标左边那半截"：
  - 光标停在名字**最左边**按 `Delete` 从头删：左边一个字符都不剩，改看光标**右边**紧挨着的
    那截残留标识符，照样按它出候选；
  - 光标停在名字**中间**删：把左边那半截 **+** 右边那半截合起来当当前词。所以把
    `test23456789` 中间那个 `t` 删成 `tes|23456789` 时，**不会**再按 `tes` 提示 `test` / `test02`，
    只提示真正的那一整段名字。
  两种情况按 `Tab` 都会把残留的**整段**换掉（不会拼出双份名字）。
- **在标识符前面敲空格 / 标点不会触发补全**：光标停在一个词的**最前面**（比如形参的
  首字符前）敲一下空格，列表只会收起，**不会**把右边那个词当成"正在输入的词"提示出来。
  这一帧跟"从词首按 Delete 删字"长得一模一样（左边是分隔符、右边是标识符），只能靠
  **这次改动的形状**区分：删字是行**变短**，敲分隔符是行**变长**且插入的这一段不含
  标识符字符。所以从词首按 `Delete` 删字仍旧照常出提示。
- **VBE 弹成员列表时，我们自动让位**：VBE 的成员列表跟我们的弹窗会出现在同一处
  （光标正下方），两个列表同时出现会互相遮挡、还抢键盘。所以 **VBE 一弹成员列表，
  我们就不再弹**，它一收起立刻恢复。两路判据（任一命中即让位）：

  - **VBE 的成员列表窗真的显示着**（精确判据，v63→v65）—— VBE 的提示窗是两个
    预建复用的真窗口（`PopupTipWndClass`、`NameListWndClass`），直接查可见性即可。
    **只有 `NameListWndClass`（列出成员 / 列出常量）让位**；`PopupTipWndClass`
    （**参数信息** = 形参签名）**不让位** —— 它只是一行只读提示、不吃键盘，而它
    出现时你正在填实参，**正是最需要候选的时候**（v65 之前在那儿让位，表现为
    "填参数的位置输入任何字符都不提示"）；
  - **光标停在 VBE 会弹列表的语法位置**（v55）—— 覆盖提示窗出现之前的那一瞬：
    - **成员访问** —— `UserForm1.`、`Me.`、`Sheet1.Range(...).` 之后输入成员名；
    - **类型位置** —— `Dim x As ` / `Set c = New ` 之后填类型名（VBE 弹类型列表）；
    - **`With` 块内的 `.成员`**（v72）—— `With Range("a1:a10").Font` 之后
      `.Size` / `.Bold` 这种**点顶在行首**的写法，以及 `a = 1: .Size`、
      `Set f = .Font`、`x = .Left + .Width` 这类点跟在语句 / 运算符边界后面的
      写法。这些位置在 VBA 里只有 `With` 块一种合法解释，VBE 都会弹成员列表。
      ⚠️ 这一条必须靠「预测语法位置」让位，**不能等 VBE 的窗真画出来再说**：
      我们的候选窗是置顶（topmost）悬浮窗，一弹出来就压在 VBE 的列表上面，
      而 VBE 的列表在失去激活时会自己收起 —— 等它可见再让，这个"让"就已经
      被我们破坏掉了（v72 修的正是这个，症状是「VBE 的弹窗反而给我们让位」）。
      另加一道兜底：候选窗挂着时，只要探到 VBE 的成员列表**真的可见**就收起
      我们的（手动 `Ctrl+Space` 点名要出来的那个除外）。
      ⚠️ **让位是「待定」的，不是一让到底**（v73）：VBE 的自动列出成员要先把
      对象的类型解析出来，`With` 块里解析不了（地址写错、模块里有待编译的
      错误）它可能**一个窗都不弹** —— 那时"让位"就等于什么都不给（症状：
      **在 With 块里输入 `.Size` 什么都不弹了**）。所以让位后会给 VBE 一个
      **0.25 秒的宽限期**：宽限内它的列表真出现就认这个让位；**没出现就把候选
      窗补回来**（VBE 的列表要是晚一步才来，上面那道兜底又会把我们收掉）。
      同一处只判定一次，不会"让开-补上-再让开-再补上"地来回抖。
      宽限期可调：`set VBECOMPLETE_YIELD_GRACE=0.6`（VBE 慢的机器上调大些）。

  按 `Ctrl+J`（VBE 列出成员）手动唤出时我们也会立刻收起；`Ctrl+Shift+I`
  （VBE 参数信息）**不会**让我们收起。
  想彻底关掉这个让位行为：`set VBECOMPLETE_NO_YIELD=1`。
  ⚠️ **v76 起让位不再区分「自动 / 手动」**：只要 VBE 的成员列表**真的画在屏幕上**，
  不管这次是你按 `Ctrl+Space` 唤出的、还是轮询自动触发的，我们都会收起来让位 ——
  理由很硬：我们的窗是 topmost 悬浮窗，一挂上去就把 VBE 的列表整个盖住。
  而你按 `Ctrl+Space` 时若 VBE 的列表**不在**（大多数情况：VBE 根本没弹），我们照旧
  弹出来给你选，所以不会变成"按了没反应"。
  同一条判据在 v76 也覆盖了**宽限期补位**那条路（补位用 `trigger(False)` 发起）：
  它从"探到 VBE 列表不可见"到真正弹出候选窗之间隔着动作队列，VBE 的列表完全可能
  已经弹出来了 —— 现在这条判据在任何触发路径下都生效，那个缝就没了。
- **参数信息（形参签名）出现时，候选窗自动下移到它下方**（v66）：既然参数信息
  不让位，两个窗就会同时在光标下方 —— 会互相遮挡。所以拿到 VBE 参数信息窗的
  屏幕矩形后，只要它和候选窗**真的重叠**，就把候选窗**挪到它下面**（留 2px），
  它一收起就回到原位。**自定义函数的参数信息一并处理** —— VBE 对自己工程里的
  过程也弹同一个窗（实测宿主进程里 `PopupTipWndClass` 全局只有**一个**、
  预建复用，内建与自定义共用它），所以按"可见的提示窗"避让就天然覆盖了。
  下移后放不下（贴到屏幕底边）时翻到光标上方；判定不了就什么都不做（宁可重叠，
  也不乱挪）。窗口类名与预期不符的机器：`set VBECOMPLETE_VBE_POPUP_CLASS=类名` 追加。
  ⚠️ **避让有两条判据，缺一不可**（v74）：① 提示窗矩形**变了**就重摆（事件驱动）；
  ② 每轮都拿候选窗**当前实际位置**复核一次，**真的还叠着**就重摆（状态自愈）。
  为什么必须加第 ② 条：只看"变没变"会漏 —— 候选窗不可见期间提示窗出现过、又回到
  同一位置，矩形签名恰好等于缓存里的旧值，"变化检测"就永远看不见它，候选窗会一直
  压在签名窗上（v74 修的正是这个：**`instr` 长签名与候选窗重叠**）。第 ② 条只花
  几次矩形比较（实测 `vbe_popup_rects()` 0.015ms/次），不依赖任何事件。
- **自动配对括号 / 引号**：敲 `(` 自动补 `)`、敲 `"` 自动补另一个 `"`，
  **光标停在中间**，接着敲内容即可。光标右边已经有那个右半边时（比如打完
  `s = "abc` 再按 `"`），只是**跨过去**、不会补出双份。
  VBE 原生并不自动闭合（只在行尾按回车时才补引号），所以由我们补上。
  注释里、有选区时不自动配对。想关掉：`set VBECOMPLETE_NO_AUTOPAIR=1`。
  ⚠️ **括号落点以★v79 的口径为准**：我们写进那一对符号后，VBE 的**自动语法检测**
  会把整行重新排版（逗号后补空格、`=` 两边补空格、关键字/函数名改大小写……），
  行一变长，写入前算好的光标位置就偏了 —— 表现为「打完 `(` 光标没落在括号中间」。
  所以写入之后会**读回 VBE 排版好的那一行**，用「插入点左边的代码压平（去空白 +
  小写）后的指纹」在行里重新认一遍那一对符号，再把光标钉到中间去。
  指纹认不出来才退回差分对齐的老办法。**一行里有好几对括号时（
  `targetSheet.Cells(i, "b").Interior.Color = RGB()`）也不会认错** —— 认的是
  指纹命中的那一对，不是"第几对"。
- **候选列表一屏最多 15 行**：候选**不足 15 行时列表高度随之缩短**（显示几行就几行高，
  不固定高度），15 行只是**一屏显示上限、不是候选上限**——候选再多也一个都不丢。
- **列表宽度固定为 30 个字符**（仿 IDEA）：不再随内容伸缩，也**没有横向滚动条**；
  名字超过 30 个字符时，超出部分用 `...` 省略。
  被省略的名字，只要它是**当前选中项**（`↑`/`↓` 选中的那行）或**鼠标悬停的那一行**，
  就会把**完整名字**显示在列表下方的一行"详情行"里（窗口按需加宽），所以选中的超长名字永远能看全。
- **候选超过 15 条时可以滚动查看**：`↑` / `↓` 或**鼠标滚轮**（指针放在弹窗上）上下浏览，
  列表**右侧**会出现**纵向滚动条**指示当前位置。
  **滚动条支持鼠标拖动**：按住左键拖动滑块、或点轨道空白处跳到对应位置。
  **在你确认选词之前，这个列表和滚动条永远不该自动消失。**
- `↑` / `↓` 选择候选（循环，走到末项再按会绕回第一项），**选好后按 `Tab` 才写回编辑器**；
  也可以用**鼠标单击/双击**候选。
- **`Shift+↑` / `Shift+↓`：跳出候选列表，光标上/下移一行**（v78）。
  列表弹着的时候 `↑`/`↓` 一直是在列表里选词、光标动不了，这一对组合键就是
  "这次我不要选词，我要把光标挪到上/下一行"的出口：**先收起我们的窗，再把光标
  平移一行（同列）**。
  刻意**不用**"放行按键让 VBE 自己动"——VBE 原生的 `Shift+↑`/`↓` 是**扩展选区**
  （会把上一行整行选进去），并不是干净地移动光标，所以这里由我们吞键、
  用 COM 直接落光标（列沿用 VBE 的显示列语义，目标行较短时由 VBE 钳到行尾）。
  接管范围与 `Shift+Enter` 同规矩：焦点必须真在**代码窗格**且 COM 可用；这两条
  不满足时**不吞键**，原样交给 VBE（退化成它的原生行为）——绝不"吞了按键却没反应"。
  想关掉这个接管（`Shift+↑`/`↓` 回到 VBE 原生语义）：
  `set VBECOMPLETE_NO_SHIFT_NAV=1`。
- **`Tab` 是唯一确认键**。
  空格和回车按普通输入处理（弹窗会自动收起，然后正常换行 / 输入空格），
  避免误把词写进编辑器。若以后想把回车也加回来：
  把 `main.py` 里的 `CONFIRM_VKS = (VK_TAB,)` 改成 `(VK_TAB, VK_RETURN)`。
- **`Shift+Enter` 在当前行下方新起一行**（仿 IDEA 的 Start New Line）：**当前行不拆分**
  ——光标右侧的代码留在原行；新行缩进与**上一行代码的起始位置对齐**，光标落在新行缩进之后。
  等价于"先把光标移到本行末尾、再按回车"，但一步到位（光标停在行中间时也照用）。
  接管范围严格限于「焦点真在 VBE 代码窗格」且「COM 可用」（v64 起判据从
  "前台是 VBE"收紧成"焦点在代码窗格"）；这两条不满足时**不吞键**，
  `Shift+Enter` 就是 VBE 原生的回车行为。裸回车、`Shift+Tab` 一律不受影响。
- **光标在行尾按回车时，自动缩进**（v79）。两条规则：
  - **整行注释**（`'...` / `Rem ...`）：忽略它、以及上方**连续的多行注释**，
    跟上方**第一个非注释行**对齐 —— 特别适合"把一段代码注释掉、接着往下写"
    的场景（注释行在第 1 列、上方代码缩进 12，回车就落在 12）；
  - **块结构开头**：`For` / `For Each` / `Do` / `Do While` / `Do Until` /
    `While` / `With` / `If … Then` / `ElseIf … Then` / `Else` / `Case …` /
    `Case Else` / `Select Case` / `Sub` / `Function` / `Property Get·Let·Set` /
    `Type` / `Enum` / `#If … Then` / `#Else` —— 新行**深一级**（默认 4 个空格）。
    单选 `If x Then y = 1`（不以 `Then` 结尾）**不算**块头；闭合行
    （`Next` / `Loop` / `Wend` / `End If` / `End Sub` …）本来就在正确层级上，
    新行跟它齐平即可，所以不做特殊处理。
  - **只在"这一下回车确实要改缩进"时才接管**（整行注释 / 块结构开头 +
    光标在行尾 + 行内没有 Tab）；普通代码行、空行、光标在行中间（那是**拆行**）、
    行内有 Tab（列语义算不准）一律**原样交给 VBE**，风险为零。
    引号没闭合时也不抢 —— VBE 原生回车会替你把右引号补上。
    ⚠️ **输入法组字中的回车绝不接管**：打拼音时按回车是**上屏**（把候选字送进
    文档），抢了它就变成"字没上屏、反而多出一行"。判据是"按了可能写字的键、
    文档却没变"（拼音被输入法吃掉）= 正在组字 —— 这是**输入法无关**的做法，
    不依赖任何 IME 接口，中/日/韩输入法一样有效。代价是：**刚打完字就立刻按
    回车**（不到一个轮询周期 100ms）那一次可能不缩进，再按一次即可。
    万一 COM 没写成，会把这一下回车**原样还给系统**（绝不"按了回车却没换行"）。
  - 一级缩进默认 **4 个空格**；工程里用 Tab 缩进就跟着用 Tab；也可
    `set VBECOMPLETE_INDENT_UNIT=2`（2 个空格）或 `=tab` 指定。
  - 想关掉（回车完全回到 VBE 原生）：`set VBECOMPLETE_NO_ENTER_INDENT=1`。
- **块头回车自动补收尾**（v79b）：上面那些**需要收尾**的块结构，在行尾按回车时
  会顺手把收尾也补出来，光标停在中间那行（缩进已经好了），可以直接写块内容：

  | 写这一行 + 回车 | 自动变成 |
  |---|---|
  | `If i = 1 Then` | `If i = 1 Then` / 缩进好的一行 / `End If` |
  | `With rng` | `With rng` / 缩进好的一行 / `End With` |
  | `Sub Foo()` | `Sub Foo()` / 缩进好的一行 / `End Sub` |
  | `Select Case x` | `Select Case x` / 缩进好的一行 / `End Select` |
  | `For i = 1 To 10` | `For i = 1 To 10` / 缩进好的一行 / `Next` |
  | `Do` | `Do` / 缩进好的一行 / `Loop` |
  | `While x` | `While x` / 缩进好的一行 / `Wend` |

  - `Function` / `Property` / `Type` / `Enum` 同理，补 `End Function` /
    `End Property` / `End Type` / `End Enum`。
  - **不补的**：`Else` / `ElseIf … Then` / `Case …` 是块**内部**的分支，往下一行
    只是同级的分支体；`#If … Then` / `#Else` 条件编译必须配 `#End If`，
    替你写个裸的 `End If` 反而把代码写错 —— 这些一律只缩进、不补。
  - **不该补的时候绝不硬塞**：下面**已经挂着**同一个收尾（`End Sub` / `Next i` /
    `Loop While x`…，隔着空行也算），或者这块的**下文已经在写了**（下面第一个
    非空行的缩进不比块头浅）—— 都只缩进、不补，免得把你已有的代码顶开。
    所以"在 `Sub` 里补 `If … Then`"这种最常见的情形是对的：下面压着 `End Sub`
    比 `If` 浅，正是"这块还没内容就该结束"，收尾就补在这儿。
  - 只在块头那行行尾按回车时触发；`Shift+Enter`（新起一行）**不补**。
  - 想只留缩进、不要补收尾：`set VBECOMPLETE_NO_AUTOCLOSE=1`。
- **`←` / `→` 也会收起列表**：和"鼠标点到别处"同义——光标移出正在拼的那个词，
  补全上下文就失效了。按键照常放行，光标该移还移。
- `Ctrl+Space` 可手动强制弹出。
- 在字符串或注释里输入不会触发。
- **支持中文命名**：中文变量/常量/过程名（如 `用户名`、`计算`）也能提取，并在输入首字时提示、补全。
- **鼠标点击其它地方自动收起**：弹窗开着时，点击弹窗以外的任意位置（包括切到别的窗口）都会自动隐藏；
  点击弹窗内的条目仍以单击/双击确认。
- **作用域感知（按 VBA 官方可见性规则）**：只提示当前位置真正可见的名字——
  1. **过程级**：当前过程的局部变量和参数；其他过程里的局部变量一律不提示。
     在**正在起新名字**的位置（形参 / 局部 `Dim`，含独占一行的**续行形参**）输入、
     回退、按退格或粘贴一个与别的过程局部变量同名的名字时，弹窗**不会**把它当作
     "已有名字"提示出来（即不会"提示自己"）。
     判据是**语义**而不是按键——那个词就是本行正在声明的名字、且它在本模块的模块级
     并不存在。（从编辑动作上区分不开：粘贴一个完整名字与手动敲出最后一个字符，
     前后两帧快照逐字符等价。）
     **只剔除与光标处完全同名的候选**：输入 `num` 仍会提示 `numArr`；本模块模块级
     真名字（如已存在的 `Sub test`）照常提示；模块声明区的声明行照常提示。
     把光标挪到形参首字符**前面**敲空格，同样保持安静。
  2. **模块级 + Private/Public**：本模块的模块级名字（含 Private）都会提示；
     其他模块里只有 **Public/Global** 的才提示，
     **Private 或默认私有（模块级 `Dim`、`Const`）的不会提示**——
     所以不会出现"在模块 B 里却提醒模块 A 的私有变量"。
  3. 类模块 / 窗体 / 文档模块（ThisWorkbook、Sheet 等）的成员只能通过
     实例或限定名访问，跨模块不提示裸名。
  4. 同名遮蔽：本过程局部 > 本模块级 > 其他模块 Public。
- 依据的官方规则：模块级 `Dim`/`Static`/`Const` **默认等效 Private**；
  `Sub/Function/Property/Type/Enum` **默认 Public**；显式 `Private` 限本模块。
- **字号自动跟随 VBE**：读注册表 `HKCU\Software\Microsoft\VBA\7.1\Common` 的
  `FontFace` / `FontHeight`，换算成磅值后**减 1**（比 VBE 小一号）；每次弹出都重新读取，
  所以你在 VBE 里改了字号，弹窗会立刻跟着变。想改偏移量调 `ui.py` 里的 `FONT_DELTA`。
- **高亮配色**：弹窗用 Canvas 自绘（`tk.Listbox` 每行只能有一种颜色，做不了部分着色）。
  未选中行白底，命中字符**红色**（`COLOR_HIT`）；选中行蓝底，命中字符改用**暖黄**
  （`COLOR_SEL_HIT`）—— 不是红色，因为红字压在深蓝底上对比度太差反而看不清。
  这些都是 `ui.py` 顶部的常量，改一行就换色。
- **位置紧贴光标**：用 Win32 `GetGUIThreadInfo` 取 VBE 代码窗光标的屏幕坐标，
  弹窗出现在光标正下方；下方空间不够时自动翻到光标上方。
- 补全范围：当前工程所有模块里的变量、常量、Sub/Function/Property 及其参数、
  Type/Enum 及成员、Declare 声明。
- **隐式变量**：不写 `Option Explicit` 时"用到即存在"的变量（从没 `Dim` 过）也能提示，
  取自赋值目标与代码里"解释不掉"的裸标识符。
  作用域按 VBA 语义归属到**首次出现所在的那个过程**（局部变量），
  因此**不会**从别的过程漏进来 —— 在别的过程**形参列表**里无论是敲、退格、粘贴，
  该名字都不会被回敬给你；只有模块顶层的隐式变量才全模块可见。
- **写了 `Option Explicit` 的模块例外**（v75）：它是强制声明，只在
  `Dim` / `Const` / `Sub` / `Function` / `Type` / `Enum` / 形参里出现过的名字才算数；
  "只用过、没声明"的名字**不再进提示池** —— 那种写法在该模块里本来就是编译错误，
  提示它只会把坏代码带出去。判定**按模块**做（`Option Explicit` 本身就是模块级
  语句）：**没写它的模块一字不动**，"用过即存在"照旧提示。
  ⚠️ 判定会先抹掉字符串与注释，所以"注释掉的那一行 Option Explicit"不算数；
  `Option Base 1` / `Option Compare Text` 也都不算。
  想回到旧行为（不分模块、隐式变量一律收）：
  `set VBECOMPLETE_IMPLICIT_HONOR_EXPLICIT=0`。

## 开机 / 打开 VBE 自动启用

每次开机都要手动 `run.bat` 太麻烦，可以把它放进开机启动：

1. 双击 **`install_autostart.bat`**：它会先装好依赖，然后在你的
   「开始菜单 → 启动」目录里创建一个指向 `pythonw main.py` 的快捷方式
   （`VbeComplete.lnk`）。
2. 之后每次 Windows 登录，工具就在后台自动运行。
3. 工具采用"焦点驱动"：只有 VBE 代码窗是前台窗口时才挂载键盘/鼠标监听，
   所以平时（你在 PyCharm、浏览器等其它程序里）它完全不装全局钩子、几乎零打扰；
   一旦你切到 VBE 写代码，它就自动生效。—— 这同时实现了"打开 VBE 时自动启用"。
4. 想取消开机自启：双击 **`uninstall_autostart.bat`** 删除该快捷方式即可。

> 说明：快捷方式指向 `pythonw.exe`，无控制台窗口、无图标，后台静默运行。

## 文件说明

- `parser.py` — VBA 标识符提取（纯文本）
- `vba_builtins.py` — VBA 语言自带名字的清单（内建函数/常量/数据类型 + 关键字）。
  ⚠️ 清单本身保持完整，但★v77 起**默认一条都不进候选池**（四个开关都默认关，
  见上文"只提示你这个工程里真实存在的东西"）
- `engine.py` — 补全引擎（触发/模糊匹配/排序/选择/插入，纯逻辑）
- `vbe_bridge.py` — 对接真实 VBE（pywin32 COM，唯一需 Excel 的部分）
- `ui.py` — 悬浮弹窗（tkinter Canvas 自绘，支持命中字符高亮）
- `main.py` — 键盘监听 + 焦点判定 + 串联各模块
- `requirements.txt` / `run.bat` — 安装与启动
- `stop.bat` / `stop.ps1` — 结束后台进程（更新版本前用）
- `install_autostart.bat` / `install_autostart.ps1` — 加入开机启动
- `uninstall_autostart.bat` / `uninstall_autostart.ps1` — 取消开机启动

## 排错

- 找不到弹窗：先确认 Excel 的"信任对 VBA 工程对象模型的访问"已勾选。
- 确认工具在跑：任务管理器里应有 `pythonw.exe`；没有就重双击 `run.bat`。
- 依赖安装失败：在命令行运行 `python main.py`，可直接看到具体报错。
- "按 Tab 后列表框不消失"或"列表框被按 Tab 也关不掉"：
  双击 **`stop.bat`** 杀掉所有 VbeComplete 进程，再双击 `run.bat` 重启一次即可。
  这通常是因为之前残留了多个旧实例（已加单实例互斥体防复发）。
- **关闭工作簿 / 退出 Excel 很卡，关完 Office 又被重新拉起**：
  通常用 `stop.bat` 结束进程后重启即可。若仍觉得慢，可用环境变量把工具调成最保守模式：

  ```bat
  set VBECOMPLETE_PROXY_TTL=0
  run.bat
  ```

  `=0` 表示彻底不缓存 COM 代理（每次用完即弃，最保守）。若怀疑宿主窗口探测误判
  （例如用 WPS 等非 Office 宿主），用 `set VBECOMPLETE_NO_WINDOW_GATE=1` 关掉窗口门。
- **两个列表还是同时出现（我们没让位）**：分两种情况看 ——
  ① 挡住的是 VBE 的**参数信息**（形参签名）：v65 起**有意不让位**（填实参时更需要
  候选），v66 起候选窗会自动**下移到签名窗下方**，两个窗不重叠。若候选窗**仍然压着**
  签名窗：v74 之前那是"变化检测漏了一次"（签名窗在候选窗不可见期间出现过又回原位），
  v74 已用"每轮实测复核"兜住。
  ② 挡住的是 VBE 的**成员列表**：v76 起只要它的列表**真的可见**，我们在**任何**触发
  路径（轮询自动 / `Ctrl+Space` 手动 / 宽限补位）下都会收起来让位。**万一还撞车**，
  跑一次 `run_debug.bat` 复现，日志里搜 `poll: trace`（v76 新增）—— 那一行把"我们这轮
  到底看到了什么"整条打出来，三种原因一眼可分：
    * `VBE提示窗=()` —— 压根没探到提示窗（类名 / 宿主 PID 的问题，见第 ③ 条）；
    * `手动=True` —— `Ctrl+Space` 的标记还挂着（v76 之后它已不再阻止让位，出现即异常）；
    * `候选窗几何=...` 与 `VBE提示窗=...` 明明相交却没被收掉 —— 窗口判据那一侧的问题。
  ③ 这台机器的提示窗类名不在探测清单里（默认认 `NameListWndClass` /
  `PopupTipWndClass`）：枚举一下 Excel 进程的顶层窗口（`EnumWindows` + `GetClassName`）
  确认真实类名后，用 `set VBECOMPLETE_VBE_POPUP_CLASS=类名` 追加（探测与避让都用这份
  清单）；若成员列表那一侧仍撞车，再用 `set VBECOMPLETE_VBE_YIELD_CLASS=类名` 追加到
  "让位清单"即可。
- **输入 `xl` / `mso` 没有任何提示（或该补的 `xl*` 常量补不出来）**：★v70 起这批
  **默认就是关的**（用户口径：内置枚举不用、嫌干扰）。想收回来先确认这几条：
  1. 是不是压根没开：`ENABLE_HOST_ENUMS=True` 或 `set VBECOMPLETE_HOST_ENUMS=1`
     （**这才是最常见的原因**）；
  2. 这批常量是**运行时从工程的"引用"里现读**的，读不到就整批不出现，而**不会**
     影响其它提示 —— 工程里得真有那两条引用（VBE 菜单 **工具 → 引用**，`Excel` 与
     `Office` 默认都在；被取消勾选过就会缺）；
  3. 家族前缀是**自动推导**的（能盖住该库一半以上成员的最长公共前缀），
     推导不出就**整库跳过**（例如 `stdole` 那种 `Checked` / `Color` 各说各话的库，
     故意不收 —— 它们全是通用词，收进来只会污染你自己的变量名）；
  4. 白名单模式：`VBECOMPLETE_HOST_ENUM_FAMILIES=xl` 只留这一族；
  5. 日志里搜 `host-enums:` —— 会写明每个库"推导出的家族前缀 + 保留多少条"，
     以及哪几个库因为"无家族前缀"被跳过。
- **提示里冒出一堆 `vb*` / `xl*` / `mso*`，觉得吵**：★v70 起**默认都不出**了 ——
  内置枚举常量（`vb*`）用 `ENABLE_VBA_CONSTANTS`、宿主枚举（`xl*` / `mso*`）用
  `ENABLE_HOST_ENUMS` 控制，两个都默认 `False`。若不慎打开了又觉得吵：
  - 只要别把它们打开就行（默认口径）；
  - 只想要某一个家族：`set VBECOMPLETE_HOST_ENUM_FAMILIES=xl`；
  - 打开状态下的防噪规则（**没打开时用不上**）：它们只在你**敲出家族前缀**时才出现
    （`xl` / `xlu` / `mso`），输 `count` / `cell` / `range` 这类词**一条都不会多出来**；
    敲了前缀之后也要打满 **4 个连续字符**才开始接受跳着命中（`xlworkfaul` →
    `xlWorkbookDefault`），所以 `xlm` / `xlc` 这种三两个字符的输入不会炸出几百条。
- **打 `ms` 不提示 `MsgBox`、打 `Dim` 不提示关键字 —— ★v77 起这是正常的，不是坏了**：
  语言自带的那四批（内建函数 / 内建数据类型 / 语言关键字 / 各种枚举）**默认一律不收**，
  候选池现在只有你自己工程里的名字（变量、自定义过程、模块 / 窗体 / 类模块名、控件名）。
  想收回来逐批开开关（改完 `stop.bat` → `run.bat` 生效）：内建函数 + 内建类型用
  `set VBECOMPLETE_VBA_BUILTINS=1`、关键字用 `set VBECOMPLETE_VBA_KEYWORDS=1`、
  `vb*` 枚举用 `set VBECOMPLETE_VBA_CONSTANTS=1`、`xl*` / `mso*` 用
  `set VBECOMPLETE_HOST_ENUMS=1`。四个开关互相独立，开哪个只影响哪一批。
- **打两个字母冒出的候选比以前多（v71）**：**只在上面那几个开关打开时才会遇到** ——
  池子里那 260 来个内建名字现在允许"跳着打"了（`ve`→`VarType`、`vr`→`VarType`），
  代价是 `se` / `ce` / `le` / `re` 这类输入会多出几条；首字母对不上的仍被挡掉
  （`xl`→`Explicit`、`ms`→`Implements` 不出）。多出来的全部落在 `kind 0` 档，
  **不会顶掉**精确 / 前缀 / 连续命中 —— 打 `ms` 第 1 个仍是 `MsgBox`。
  嫌多就用 `set VBECOMPLETE_BUILTIN_SCATTER_MIN=4` 退回 v61~v70 的老口径。
- **某个"用过但没声明"的变量名不再提示了（v75）**：这是**按模块**生效的 ——
  该模块的**第一行附近写了 `Option Explicit`**（强制声明），于是只用过、从没
  `Dim` 过的名字不再进池子（那种写法在该模块里是编译错误）。
  逐条排查：
  1. VBE 里打开那个模块，看顶部有没有 `Option Explicit`（注释掉的**不算**）；
  2. 想让它照旧提示：给这个名字补一行 `Dim`，或整批回到旧行为 ——
     `set VBECOMPLETE_IMPLICIT_HONOR_EXPLICIT=0`；
  3. 只想要"完全不收隐式变量"（连没写 `Option Explicit` 的模块也不收）：
     那是另一个更老的开关，改源码里的 `vbe_bridge.ENABLE_IMPLICIT_IDENTIFIERS`。
  日志里搜 `不收集隐式变量` —— 被闸掉的模块会逐行列出来
  （`mod=CopyPicturesToCells Option Explicit -> 不收集隐式变量`）。
- **`xl` 后面只打两个字母（`xlde` / `xd`）补不出 `xlWorkbookDefault`**（**打开**宿主
  枚举时才会遇到）：这是**故意的**，别再放宽 —— 放宽了也不会出现，只会更糟。
  实测真机 4538 条：
  `xlde`（家族前缀 + 2 字母）若接受"跳着凑"，会命中 731 条，而目标排在**第 291 位**；
  连家族前缀都不要求（`xd`）则是 1032 条、目标排**第 450 位**。
  候选窗一屏只有 15 行 —— 目标躺在第 291 位 = 翻 20 屏也看不到，还会把
  `ms`→233 条、`open`→484 条这类噪音全带回来。
  **原因不是规则太紧，是 `xlWorkbookDefault` 对这种输入本来就是"弱匹配"**：
  `xlDe` 对 `xlDefault` / `xlDelimited` 是连着打中的，对它却跳过了 8 个字符。
  想让它当场浮上来，就**连着打 4 个字母**：`xlwo`（9 条，可见）/ `xlwork`（31 条，第 9）/
  `xlworkf`（2 条，第 2）/ `xlworkfaul`（1 条，第 1）。
- **`Shift+↑` / `Shift+↓` 只是选中了一行、光标没"干净地上移"**：说明这一下没被我们
  接管，VBE 按原生语义（扩展选区）处理了。三种可能：
  ① 跑的是 v78 之前的代码（`stop.bat` → `run.bat` 重新加载）；
  ② 设了 `VBECOMPLETE_NO_SHIFT_NAV=1`（去掉即可）；
  ③ 当时焦点不在代码窗格、或 COM 正处于失败退避 —— 这时我们**刻意不吞键**，
  把按键原样交回 VBE。日志里搜 `navline:` 能直接看到第 ③ 种
  （`navline: COM 未落成 -> 按键原样还给系统`）。
- **括号 / 引号不想自动配对**：`set VBECOMPLETE_NO_AUTOPAIR=1`。
  若只是偶尔想只敲半边：先按一下 `"` 补出一对、光标在中间，直接输入内容即可；
  结对后按 `"` / `)` 是"跨过去"，不会多出字符。
- **打完 `(` 光标没落在括号中间**（比如 `… = RGB(` 之后光标跑到别处）：
  ★v79 已修。成因是 VBE 的自动语法检测把整行重排了（补空格 / 改大小写），
  按老位置落光标就会偏。现在会在读回重排后的行、按"插入点左边的代码"重新
  定位那一对符号。**若还遇到**，跑 `run_debug.bat` 复现一次，日志里搜
  `autopair: VBE 重排了整行` —— 那一行会写出「我们写入的行 / VBE 实际的行 /
  重新定位到的位置」，三种情况一眼可分：没这条日志（VBE 根本没重排，那就是
  我们算错了写入位置）；有日志且 `定位=None`（指纹与差分都没认出来）；
  有日志且定位值看着不对（把 `实际=` 那一行发我即可）。
- **回车没有自动缩进 / 注释行回车还是顶格**：先确认这两条前提 ——
  ① 是 **v79 之后**的代码（`stop.bat` → `run.bat` 重新加载）；
  ② 没设 `VBECOMPLETE_NO_ENTER_INDENT=1`。
  仍然不缩进时，逐条对号（这些都是**刻意不接管**的情形）：
  - 当前行不是整行注释、也不是块结构开头（普通代码行回车本来就"与自身齐平"）；
  - 光标**不在行尾**（光标后面还有内容）—— 那是拆行，必须交给 VBE；
  - 当前行是**空行**（只有空白）：交给 VBE 继承上一行缩进，免得跟你手动排的
    缩进较劲；
  - 行内用了 **Tab** 缩进：列语义算不准，这一行不接管（要用 Tab 缩进就把
    `set VBECOMPLETE_INDENT_UNIT=tab` 设上，一级缩进会跟着用 Tab）；
  - 引号没闭合：留给 VBE 补右引号；
  - **输入法正在组字**（打拼音的字还没上屏）：这一下回车是**上屏键**，交给输入法
    —— 判据是"按了可能写字的键、文档却没变"，所以**刚打完一个词就立刻按回车**
    （不足 100ms）可能碰上这一次不缩进；
  - 判据读的是**轮询快照**（100ms 一次、最多 0.8 秒旧）：光标刚移动/刚切了
    模块后紧跟着按的回车，可能这一次不接管 —— 再按一次即可。
  日志里搜 `enterindent:`：出现 `未接管 -> 回车原样还给系统` 说明这一刻
  后端判定"不该由我们写"（上面某一条），回车本身仍然照常发生。
- **回车没有自动补收尾（`End If` / `End With` / `End Sub` 没出来）**：逐条对号 ——
  ① 先确认是 **v79b 之后**的代码（`stop.bat` → `run.bat`），且没设
  `VBECOMPLETE_NO_AUTOCLOSE=1`；
  ② 这一行本来就**不需要收尾**：`Else` / `ElseIf … Then` / `Case …`（块**内**的分支）、
  `#If … Then` / `#Else`（必须配 `#End If`）、整行注释、普通代码行 —— 一律只缩进；
  ③ 下面**已经挂着**同一个收尾（`End Sub` / `Next i` / `Loop While x`…，隔着空行也算），
  或这块的**下文已经在写了**（下面第一个非空行的缩进不比块头浅）—— 这时**刻意不补**，
  免得把你已有的代码顶开（判据见 `vbe_bridge.closer_needed`）；
  ④ 不是"块头那行**行尾**"按的回车（`Shift+Enter` 新起一行从不补）。
  这时按回车只是**多了一行**（收尾那行），不想要删掉它即可。
- **在属性窗口 / 工程窗口 / 窗体设计器里也冒提示**：v64 起不该发生了 —— 提示只在
  焦点真处于**代码窗格**时出现。这类工作区里同样不会替你做自动配对 / `Shift+Enter`。
  若你的宿主代码窗格窗口类名不是实测的 `VbaWindow`（或这道闸门误判）：
  `set VBECOMPLETE_NO_CODE_AREA_GATE=1` 退回旧判据；
  宿主主窗口类名不是 `wndclass_desked_gsk` 时可用
  `set VBECOMPLETE_VBE_FRAME_CLASS=你的类名` 追加（先用 `EnumWindows` +
  `GetClassName` 枚举 Excel 进程的窗口确认真实类名）。
- **反过来：该弹的时候老是不弹（让位误判）**：用 `set VBECOMPLETE_NO_YIELD=1`
  关掉让位，工具就回到「VBE 弹它的、我们弹我们的」的老行为。
  另外记得：手动按 **`Ctrl+Space`** 永远能唤出我们的列表，哪怕正停在 `对象.` 后面。
  想排查"某处输入什么都不弹"：跑 `run_debug.bat`，日志里 `trigger:` / `poll:`
  两行会写清当时走的是哪条分支（是否让位、让位的是哪个提示窗、焦点落在哪）。
  另注：v65 起焦点判据把 VBE 自己的**提示窗**也算作"仍在代码窗格"—— 否则它一抢到
  焦点，我们的候选窗就会被当场收掉（那也是"输入什么都不弹"的一个成因）。
- **在 `With` 块里输入 `.Size` / `.Bold` 什么都不弹**（v73 已修；若还遇到按此排查）：
  这个位置我们是**让位给 VBE 的成员列表**的。可 VBE 的自动列出成员要先把 `With`
  的对象类型解析出来 —— 解析不了（`With Range("a1:10")` 这种地址写错、模块里
  有待编译的错误）它就**一个窗都不弹**，于是"让位"变成"什么都不给"。v73 起让位
  是**待定**的：宽限 0.25 秒后若 VBE 没弹，我们就把候选窗补回来。若仍无提示：
  1. 看 `With` 后面那串能不能解析出类型（在别处写 `Dim x As 那个类型`，VBE 认不认）；
  2. VBE 菜单 **调试 → 编译**（或 `Alt+D`→`L`）把工程编译一遍 —— 有编译错误时
     VBE 的自动列出成员会整体失灵，那时我们只能自己顶上；
  3. `set VBECOMPLETE_YIELD_GRACE=0.6` 把宽限期调大（VBE 慢的机器）；
  4. 想立刻验证是不是让位在捣鬼：`set VBECOMPLETE_NO_YIELD=1` 重启，回到"各弹各的"。

## 更新后如何生效

Python 在**启动时**把 `.py` 读进内存，只替换文件而不重启进程，跑的仍然是旧代码。
所以更新后请务必：**`stop.bat` → 覆盖文件 → `run.bat`**。
