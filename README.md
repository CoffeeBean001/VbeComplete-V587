# VbeComplete — VBA 变量名/过程名自动补全工具

在 VBE（VBA 编辑器）代码窗里输入变量/过程名的首字母（或中文首字），自动弹出候选列表，
`Tab` 确认补全，`↑`/`↓` 选择，`Esc` 取消；**鼠标点击其它地方，弹窗会自动消失**。
支持中文命名的变量/常量/过程（如 `Dim 用户名 As String`）。解决 VBE 原生只对"对象.成员"
弹列表、但不对自定变量名弹列表的痛点。

## 技术栈

- **Python** + `pywin32`（驱动 VBA 编辑器 COM）+ `pynput`（全局键盘监听）+ `tkinter`（弹窗）
- 核心解析与补全逻辑是纯 Python，不写任何日志文件、不含测试与调试代码。

## 安装与运行

1. 确保本机已安装 Python 3.8+（建议从 python.org 安装，并勾选"Add to PATH"）。
2. 首次运行会自动 `pip install` 依赖，请**以能联网的普通用户**双击 `run.bat`
   （后台静默运行）。若想看报错，在命令行运行 `python main.py`（带控制台）。
3. 在 Excel 中开启权限（必须）：
   **文件 → 选项 → 信任中心 → 信任中心设置 → 宏设置 →**
   **勾选"信任对 VBA 工程对象模型的访问"**。
4. 打开 VBE（`Alt+F11`），在代码窗输入一个变量名的首字母，即可看到补全列表。

## 使用

- 输入字母/数字/`_` 即弹列表；继续输入会实时过滤。
- **模糊匹配：不要求从首字母开始**。只要输入的几个字符**按顺序**出现在名字里就会提示，
  **命中的字符标红**，一眼看出为什么它被匹配到。例如定义了 `dataArr` 和 `dataSheet`：
  - 输入 `ts` → 提示 `dataSheet`（da**t**a**S**heet，`datasheet` 里没有连续的 `ts`，
    所以按**词边界**命中两个 `t`/`S`）；
  - 输入 `ta` → 同时提示 `dataArr` 和 `dataSheet`（两边都是连续的 **ta**）；
  - 输入 `ds` → 提示 `dataSheet`（**D**ata**S**heet，camelCase 词首缩略）；
  - 输入 `arr` → 提示 `dataArr`（data**Arr**，优先命中连续块，而不是散着凑字母）。
  候选按「精确 > 前缀 > 词首缩略 > 连续块 > 分散」排序，同级再比命中是否更靠前、
  跨度是否更小、名字是否更短——最像的永远排第一，列表不会因为放开了模糊匹配就变乱。
  输入普通前缀（如 `num`）时结果与原来完全一致，不会平白多出一堆噪音。
- **打全名照样提示**：名字打全了列表不会消失（`Sub tes` → `Sub test` 始终提示 `test`），
  包括**正在写函数/变量声明行**的时候——只要那个名字在工程里真实存在就一直提示。
  真正会被剔掉的只有"幻影词"：工程里哪都不存在、只是你正在敲的那几个字符
  （比如回退删出来的 `numA`），那才叫"提示自己"。
- **从名字的结尾 / 中间 / 开头删字符，都会继续出提示**（v44 引入；v46 完善）。
  当前词取的是「**光标所在处那一整个名字**」，而不是"光标左边那半截"：
  - 光标停在名字**最左边**按 `Delete` 从头删（v44）：左边一个字符都不剩，改看光标**右边**紧挨着的
    那截残留标识符，照样按它出候选；
  - 光标停在名字**中间**删（v46）：把左边那半截 **+** 右边那半截合起来当当前词。所以把
    `test23456789` 中间那个 `t` 删成 `tes|23456789` 时，**不会**再按 `tes` 提示 `test` / `test02`，
    只提示真正的那一整段名字。
  两种情况按 `Tab` 都会把残留的**整段**换掉（不会拼出双份名字）。
- **候选前面不再带序号**（v40 移除）：数字键选词已去掉，序号也就没必要显示了，
  列表里直接就是名字本身。候选**不足 15 行时列表高度随之缩短**（显示几行就几行高，**不再固定高度**），
  15 行只是**一屏显示上限、不是候选上限**——候选再多也一个都不丢。
- **列表宽度固定为 30 个字符**（v42，仿 IDEA）：不再随内容伸缩，也**没有横向滚动条**；
  名字超过 30 个字符时，超出部分用 `...` 省略。
  被省略的名字，只要它是**当前选中项**（`↑`/`↓` 选中的那行）或**鼠标悬停的那一行**，
  就会把**完整名字**显示在列表下方的一行"详情行"里（窗口按需加宽），所以选中的超长名字永远能看全。
- **候选超过 15 条时可以滚动查看**：`↑` / `↓` 或**鼠标滚轮**（指针放在弹窗上）上下浏览，
  列表**右侧**会出现**纵向滚动条**（贴在列表右边界，不再浮在中间）指示当前位置。
  **滚动条支持鼠标拖动**：按住左键拖动滑块、或点轨道空白处跳到对应位置。
  **在你确认选词之前，这个列表和滚动条永远不该自动消失**（v41 起弹窗带 `WS_EX_NOACTIVATE`
  永不抢焦点，且交互期间（按住/拖动）与鼠标停在弹窗上时外部逻辑不会收起它）。
- **数字键不再用于选词**（v39 移除）：避免“想打变量 `s1`，却因先按 `s` 再按 `1` 误选 `sheet1`”的冲突。
  选择只走 `↑` / `↓` + `Tab`，或**鼠标单击/双击**候选（点击经 `_row_at()` 换算成真实下标）。
- `↑` / `↓` 选择候选（循环，走到末项再按会绕回第一项），**选好后按 `Tab` 才写回编辑器**。
- **`Tab` 是唯一确认键**。
  空格和回车按普通输入处理（弹窗会自动收起，然后正常换行 / 输入空格），
  避免误把词写进编辑器。若以后想把回车也加回来：
  把 `main.py` 里的 `CONFIRM_VKS = (VK_TAB,)` 改成 `(VK_TAB, VK_RETURN)`。
- `Esc` 取消；鼠标单击/双击候选也可确认。
- **`←` / `→` 也会收起列表**：和"鼠标点到别处"同义——光标移出正在拼的那个词，
  补全上下文就失效了。按键照常放行，光标该移还移。
- `Ctrl+Space` 可手动强制弹出。
- 在字符串或注释里输入不会触发。
- **支持中文命名**：中文变量/常量/过程名（如 `用户名`、`计算`）也能提取，并在输入首字时提示、补全。
- **鼠标点击其它地方自动收起**：弹窗开着时，点击弹窗以外的任意位置（包括切到别的窗口）都会自动隐藏；
  点击弹窗内的条目仍以单击/双击确认。
- **按 `←` / `→` 也自动收起**：效果同上，且按键本身会正常传给 VBE（光标照常移动）。
  收起后不会被立刻弹回来——轮询只在"行号 + 行文本"变化时才判定要不要弹。
- **作用域感知（按 VBA 官方可见性规则）**：只提示当前位置真正可见的名字——
  1. **过程级**：当前过程的局部变量和参数；其他过程里的局部变量一律不提示。
  2. **模块级 + Private/Public**：本模块的模块级名字（含 Private）都会提示；
     其他模块里只有 **Public/Global** 的才提示，
     **Private 或默认私有（模块级 `Dim`、`Const`）的不会提示**——
     所以不会出现"在模块 B 里却提醒模块 A 的私有变量"。
  3. 类模块 / 窗体 / 文档模块（ThisWorkbook、Sheet 等）的成员只能通过
     实例或限定名访问，跨模块不提示裸名。
  4. 同名遮蔽：本过程局部 > 本模块级 > 其他模块 Public。
- 依据的官方规则：模块级 `Dim`/`Static`/`Const` **默认等效 Private**；
  `Sub/Function/Property/Type/Enum` **默认 Public**；显式 `Private` 限本模块。
- **字号自动跟随 VBE**：读注册表 `HKCU\Software\Microsoft\VBA\7.1\Common` 的
  `FontFace` / `FontHeight`，换算成磅值后**减 1**（比 VBE 小一号）；每次弹出都重新读取，
  所以你在 VBE 里改了字号，弹窗会立刻跟着变。想改偏移量调 `ui.py` 里的 `FONT_DELTA`。
- **高亮配色**：弹窗用 Canvas 自绘（`tk.Listbox` 每行只能有一种颜色，做不了部分着色）。
  未选中行白底，命中字符**红色**（`COLOR_HIT`）；选中行蓝底，命中字符改用**暖黄**
  （`COLOR_SEL_HIT`）—— 不是红色，因为红字压在深蓝底上对比度太差反而看不清。
  这些都是 `ui.py` 顶部的常量，改一行就换色。
- **位置紧贴光标**：用 Win32 `GetGUIThreadInfo` 取 VBE 代码窗光标的屏幕坐标，
  弹窗出现在光标正下方；下方空间不够时自动翻到光标上方。
- 补全范围：当前工程所有模块里的变量、常量、Sub/Function/Property 及其参数、
  Type/Enum 及成员、Declare 声明。
- **隐式变量**：不写 `Option Explicit` 时"用到即存在"的变量（从没 `Dim` 过）也能提示，
  取自赋值目标与代码里"解释不掉"的裸标识符；默认本模块可见、跨模块不提示。

## 开机 / 打开 VBE 自动启用

每次开机都要手动 `run.bat` 太麻烦，可以把它放进开机启动：

1. 双击 **`install_autostart.bat`**：它会先装好依赖，然后在你的
   「开始菜单 → 启动」目录里创建一个指向 `pythonw main.py` 的快捷方式
   （`VbeComplete.lnk`）。
2. 之后每次 Windows 登录，工具就在后台自动运行。
3. 工具采用"焦点驱动"：只有 VBE 代码窗是前台窗口时才挂载键盘/鼠标监听，
   所以平时（你在 PyCharm、浏览器等其它程序里）它完全不装全局钩子、几乎零打扰；
   一旦你切到 VBE 写代码，它就自动生效。—— 这同时实现了"打开 VBE 时自动启用"。
4. 想取消开机自启：双击 **`uninstall_autostart.bat`** 删除该快捷方式即可。

> 说明：快捷方式指向 `pythonw.exe`，无控制台窗口、无图标，后台静默运行。

## 内存占用与资源清理（是否会占很多内存？）

- **占用很低**：工具本身是常驻的轻量 Python 后台进程，日常内存约 **30–60 MB**
  （tkinter + pynput + pywin32 的基础开销）。它不会缓存整个工程，只缓存一层
  "标识符列表"，且每 2 秒最多刷新一次，普通 VBA 工程也就几百条记录，体积可忽略。
- **VBE / Excel 关闭后会自动清理**：
  - 切出 VBE（或关闭 Excel）时，工具会立刻**卸载全局键盘/鼠标钩子**并清空标识符缓存；
  - **丢弃 Excel/VBE 的 COM 代理**（`_release_vbe_proxy`）并主动 `gc.collect()`，
    确保不留悬空的 Excel COM 引用拖住 Excel 进程；
    （注意：不是靠 `CoFreeUnusedLibraries()` —— 它释放不了**我们自己持有**的
    引用，在 Excel 关闭期间调用反而惊扰 COM，默认已不再调用。）
  - Excel/VBE 的代理还带 **1 秒 TTL**，到期主动放手，绝不长期持有；
  - 所以关闭 VBE 后，相关内存会及时回收，不会越用越多。
- 如果你怀疑有残留实例，双击 `stop.bat` 一键结束所有进程即可。

## 排错

- 找不到弹窗：先确认 Excel 的"信任对 VBA 工程对象模型的访问"已勾选。
- 确认工具在跑：任务管理器里应有 `pythonw.exe`；没有就重双击 `run.bat`。
- 依赖安装失败：在命令行运行 `python main.py`，可直接看到具体报错。
- "按 Tab 后列表框不消失"或"列表框被按 Tab 也关不掉"：
  双击 **`stop.bat`** 杀掉所有 VbeComplete 进程，再双击 `run.bat` 重启一次即可。
  这通常是因为之前残留了多个旧实例（新版已加单实例互斥体防复发）。
- **关闭工作簿 / 退出 Excel 很卡，关完 Office 又被重新拉起**：
  这是 COM 引用没及时释放的典型症状（改过 VBA 代码时尤其明显，因为 Excel 退出时
  要把 VBAProject 写回文件）。新版已有三道防线（1 秒 TTL / 宿主窗口门 /
  写完代码即放手）。若仍觉得慢，可用环境变量把工具调成最保守模式：

  ```bat
  set VBECOMPLETE_PROXY_TTL=0
  run.bat
  ```

  `=0` 表示彻底不缓存 COM 代理（每次用完即弃，最保守，代价是多一次 ROT 查询）。
  若怀疑宿主窗口探测误判（例如用 WPS 等非 Office 宿主），用
  `set VBECOMPLETE_NO_WINDOW_GATE=1` 关掉窗口门。

## 实现要点（踩过的坑，供后续迭代参考）

1. **pynput 回调绝不能 `return False`**——那是"停止监听器"的语义
   （源码 `pynput/_util/__init__.py`：`if f(*args) is False: raise StopException()`）。
   之前"只能弹一次"就是这个原因：按一次 Tab/Enter 监听器就死了。
2. **pynput 回调里抛任何异常也会停止监听器**（`_emitter` 捕获后调 `stop()`）。
   所以所有回调体都用 `try/except` 包住。
3. **要吞掉按键**（不让 Tab/Enter 传到 VBE）必须用 Windows 专用的
   `win32_event_filter` + `listener.suppress_event()`，已在本机 pynput 上验证可用。
4. 所有改 UI / 调 COM 的动作都经队列交给 tkinter 主线程，避免跨线程问题。
5. 内置看门狗：监听器若意外死亡会每 2 秒自动重启，保证能一直用。
6. **作用域（v3：模块级 + Private/Public）**。标识符记录为四元组
   `(name, module, proc, priv)`：
   - `parser.extract_records(code, module, is_std_module)` 产出完整记录；
     模块级 `Dim`/`Static`/`Const` 默认私有（`priv=True`），
     `Sub/Function/Property/Type/Enum` 默认公共，显式关键字覆盖默认；
     类/窗体/文档模块（非标准模块）的所有成员一律按"模块私有"处理。
   - `engine.filter_identifiers_by_scope(ids, proc, module)` 过滤：
     本过程局部（同模块同过程）> 本模块模块级 > 其他模块 Public，
     其他模块 Private 直接跳过。旧式二元组/纯名字列表仍兼容
     （module=None 视为全局可见），旧式数据仍兼容。
   - 光标所在模块名由 `CodeModule.Name` 实时取；
     过程名仍走 `parser.proc_at_line()` 纯文本扫描（ProcOfLine 兜底）。
   - **修复了带修饰符的 Type/Enum 声明**（`Public Enum Color` 之类）
     被误当成变量声明解析的旧 bug：`_RE_TYPE/_RE_ENUM` 改为
     `^\s*(?:(?:Public|Private|Friend|Global)\s+)*Type|Enum\s+...` 锚定。
7. **取光标位置**：pywin32 的 `win32gui` 没有 `GetGUIThreadInfo`，
   改用 `ctypes` 直接调 `user32.GetGUIThreadInfo` + `ClientToScreen`。
8. **VBE 字号**在注册表 `HKCU\Software\Microsoft\VBA\7.1\Common`：
   `FontFace`(字符串) / `FontHeight`(像素)。磅值 = 像素 / `root.winfo_fpixels("1p")`，
   可自动适配系统 DPI。
9. **"按 Tab 后弹窗不消失"的根因**（已修）：多个后台实例 + 主线程 after 队列时序。
   修法：
   - `acquire_single_instance()` 用 Windows 互斥体保证**只有一个实例**在跑（多实例会各弹一个列表框，B 实例的不会被 A 的 accept 收回）；
   - `ui.Popup` 用 `_want_visible` 标志 + `_cancel_pending_show()` 取消**已排进队列但还没执行的 `_show`** —— 否则按 Tab 收起后，刚才排在队列里的 `_show` 还会再冒出来；
   - `engine.Completer` 的 `accept()` 增加 **350ms 静默期** (`_suppress_until`)，忽略这段期间的 `trigger` 调用，避免"队列尾巴"又把它弹回来。
10. **"Tab 后光标落在词中间"的修复（坐标语义）**：根因是行内用 Tab 缩进时，
    字符位置与 VBE 的"列"可能不一致（Tab 展开成多格）。修法：
    - `vbe_bridge._vbe_measure()` 向"远超行尾"的列 SetSelection 再读回停靠列
      （字符语义被钳制到 `len+1`，显示语义钳制到"显示宽+1"，数值不同可区分），
      从而探测该行列语义与 Tab 宽度，无需预知。
    - `get_context` 把光标显示列换算成字符列（引擎的词提取/替换与行文本对齐）；
      `apply_completion` 写回后把词尾字符列换算回显示列再 SetSelection
      （并先读回实际行、以补全词为锚重新定位，兼容 VBE 对行的规范化）。
    - 相关纯函数：宽度展开 / 列换算 / 语义探测 / 整词锚定。

11. **"和 PyCharm 等程序冲突（关不掉）"的修复**：根因是之前**一直挂着
    `WH_KEYBOARD_LL` 全局键盘钩子**（Java 系 IDE 如 PyCharm/IntelliJ 退出时会等待钩子链，
    被我们的钩子卡住而关不掉）。改为**焦点驱动**：`main.py` 的 `reconcile()`
    每 300ms 检查前台窗口是不是 VBE 代码窗——是才挂载键盘+鼠标钩子，
    不是就立刻 `listener.stop()` 卸载。这样在 PyCharm/其它程序里根本不装钩子，冲突消失。
    同时这也让"打开 VBE 自动生效"自然实现（工具常驻，进 VBE 自动挂载）。
12. **中文命名标识符支持**：`engine._IDENT`、`parser._IDENT` 改为 Unicode 感知的
    `[^\W\d]\w*`（首字符字母/下划线、其余字母/数字/下划线，含中文）；
    `vbe_bridge._IDENT_TAIL` 改为 `_is_ident_tail(ch)`，用 `ch.isalnum() or ch=="_"`
    （同样含中文）。
13. **资源清理**：离开 VBE / 关闭 Excel 时，`VbeBackend.release()` 清空标识符缓存并
    丢弃 COM 代理，避免悬空引用拖住 Excel 进程、也不让内存长期占用。
    鼠标点击弹窗外自动收起由 `engine.maybe_hide_on_outside_click`
    + `ui.Popup.contains_point` 实现（全局鼠标监听只在 VBE 聚焦时挂载）。
14. **绝不长期持有 Excel 的 COM 代理**（v26，详见下面的变更记录）：代理带 1 秒 TTL，
    宿主窗口消失后不再新建，写完 VBA 代码立刻放手。这是"关文件卡 3~10 秒、

16. **「回声候选」必须剔除，判定要用现场证据；正在编辑的模块一律以它的现场文本为准**
    （v35 起，v43 / v45 补全）。光标处正在输入的那个词 —— 以及它**更长的旧版本** —— 会被标识符池
    当成一个名字收进来；把它提示出来就等于"打什么提示什么"。判断"它是真名字，还是只是我的回声"
    用两路互补证据：
    ① **现场扫描当前模块** `backend.names_outside_caret(caret)`：把光标处那个词抹掉后，模块里
       还出现过的名字。这是**权威证据** —— **正在编辑的模块一律以它为准**，现场没有就是没有；
    ② **声明集合只认【别的模块】**（`backend.get_declared_names()` +
       `backend.declared_elsewhere(name, module)`）：跨模块的 Public 名字现场扫不到，
       只有它认得。
    **不能只信缓存**：池子最快 0.4s 才刷新一次，连删时缓存里还留着那些旧名字；若拿"声明集合"
    给它们作证，就会把"回退途中更长的旧片段"保下来 —— 这正是 v43 修的毛病。兜底规则：候选若
    恰好等于"收集标识符那一刻光标处的词"（`backend.caret_word_at_collect()`）、且现场扫不到它，
    一律剔除。现场证据拿不到（后端没实现 / COM 读失败返回 `None`）时退回"声明集合"，不误杀。
    **「回声候选」的判据（v45 定型）**：**候选名包含"当前词"这一整段连续片段**。用户删除字符只会让光标
    处的词**变短**，剩下的必然是原词的连续一段 —— 从结尾删剩**前缀**（v43 修的），从开头删剩
    **后缀**（v45 修的），从两头都删剩**中段**。v43 只判了 `startswith`（前缀），所以"从开头删"
    的回声漏了过去。判据只负责挑出"需要盘问的候选"，**是否保留仍由上面两路现场 / 声明证据裁决** ——
    真名字（本模块别处出现 / 别的模块声明过）一律照常提示。

17. **取词要覆盖"光标停在标识符开头"**（v44）。`engine.extract_word_at(line_text, caret_col)`
    分两步：① 光标**左边**有词就取它（内部仍走 `extract_word_before`，与旧行为逐字一致，覆盖
    正常打字和"从结尾 / 中间删"）；② 左边取不到时，再看光标**右边**紧挨着的标识符（新正则
    `_IDENT_FWD`）—— 用户把光标停在名字最左边按 `Delete` 从头删字符就是这一种。返回值多了
    一个 `end_col`（补全词范围右端，1-based 开区间）：正常等于光标列，只有第 ② 种情形才大于
    它；`accept()` 把它交给 `backend.apply_completion(line_no, start, end, name)` 作为第三个
    参数（该参数因此由 `caret_col` 更名成 `end_col`），**把光标右边那截残留名字一起换掉** ——
    否则会在残留词前面插入候选、拼出 `abc` + `bcDef` 这种双份名字。
    配套：`_ident_char_before_caret` 的判据从"光标**前**一个字符是标识符字符"放宽为"光标**前或
    后**一格是标识符字符"，否则轮询路径会在名字开头先一步判成"没在拼标识符"把弹窗收起。
    这不会破坏"打空格收起"：在词尾敲空格后光标右边通常是行尾或括号，右边没有标识符字符，依旧收起。

    **v46 修正**：第 ① 步不能只取左边那半截。光标停在名字**中间**删字符时（`test23456789` 删掉中间的
    `t` → `tes|23456789`），只取左边的 `tes` 就会按它的前缀算候选，把 `test` / `test02` 提示出来，
    完全无视光标右边还留着的 `23456789`。现在第 ① 步取到左半截后，**继续往右吞掉紧邻的标识符字符**，
    当前词 = 整段名字（左半截 + 右半截），`end_col` 随之盖住整段 —— `tes23456789` 既不匹配 `test`
    也不匹配 `test02`，只剩真正那一整段名字，`Tab` 一次把整段换掉。判据仍是"光标前/后一格是标识符
    字符"（`_ident_char_before_caret`），无需改动。

## 变更记录

- **v27（修复：开着 VbeComplete 时，关闭 VSCode / PyCharm 等其它 IDE 卡死、关不掉）**

  现象：先启动 VbeComplete（常驻监听 Excel VBE），再去 VSCode / PyCharm 写 Python，
  关闭这些 IDE 时会卡死、无法退出。

  根因：v26 里 `reconcile()` 用 `released` 标志位管理资源，逻辑跑偏——一旦离开 VBE
  超过宽限期、`released` 变成 `True`，其后每次轮询都走 `else` 分支，**把全局键盘钩子
  + 全局鼠标钩子重新挂上**，即便你正在其它程序里。`pynput` 装的是系统级
  `WH_KEYBOARD_LL` / `WH_MOUSE_LL`，只要挂着，全系统输入事件都要先经过它的钩子线程；
  别的程序退出、拆窗口时一旦被这个钩子挡住就会卡死。这恰好是 `reconcile()` 注释里
  早就警告过的「PyCharm 关不掉」坑，被 v26 的 `released` 逻辑重新踩了一遍。

  修复：把「钩子挂载 / 卸载」和「COM 释放」两条逻辑解耦。新增纯函数
  `_reconcile_resources(focused, released, backoff, last_focus_time, now, grace)`，
  **钩子是否挂载只由「焦点是否在 VBE」决定**，离开 VBE 立刻 `stop()` 拆掉，绝不因
  `released` / COM 退避而重新挂载；COM 释放仍按宽限期 / 退避处理。

  * 回归测试新增第 18 节（7 条，纯逻辑、无需 Excel），共 **120 PASS / 0 FAIL**。

- **v28（再修：ide 关闭仍卡死 —— 加「前景窗口正在关闭就不挂钩」判断）**

  现象：v27 之后，关 IDE 偶发依旧卡死。

  根因：v27 只把钩子绑定到"焦点是否在 VBE"，但 `reconcile()` 有**焦点去抖**
  （约 600ms）。关闭 IDE 时，焦点离开 VBE 的去抖窗口内仍维持 `focused=True`，
  钩子继续挂着，于是 IDE 退出流程被 `WH_KEYBOARD_LL` 钩子挡住卡死。

  修复：新增 `foreground_window_closing()`——每周期用
  `SendMessageTimeout(WM_NULL, SMTO_ABORTIFHUNG, 200ms)` 探测前台窗口是否还
  响应；正在退出的 IDE 主线程被阻塞、会超时，判定为"正在关闭"。`_reconcile_resources`
  增加 `closing` 入参，**只要检测到前台窗口正在关闭，即使去抖仍维持"在 VBE"也强制

- **v29（再修：关 IDE 窗口后要 2~3 秒才真正退出）**

  现象：v28 之后 IDE 能关掉了，但关 VSCode / PyCharm 时窗口关了却要等 2~3 秒

## 如何确认新版本已生效

Python 在**启动时**把 `.py` 读进内存，只替换文件而不重启进程，跑的仍然是旧代码。
更新后请务必：`stop.bat` → 覆盖文件 → `run.bat`。

若行为与预期不符，先确认运行的目录里确实是新文件。在**程序实际所在目录**执行：

```bat
findstr /C:"declared_by_proc" parser.py
findstr /C:"CodeModule.Parent.Name" vbe_bridge.py
```

两条都有输出即为 v18；没有输出说明覆盖到的不是新文件（常见于把工具装在别处，
只覆盖了工作区副本）。最省事的做法：**删除旧目录，重新解压 `VbeComplete.zip`**。

## 排障：某个变量为什么不提示

1. **先跑回归测试**（不需要 Excel）：双击 `run_tests.bat`。
   全部 PASS 说明解析层没问题，问题在运行时。
2. **再开诊断日志**：`stop.bat` → 双击 `run_debug.bat` → 在 VBE 里复现一次
   → 双击 `show_log.bat`。

日志里重点看这几行：

```
boot: 运行目录=...              <- 确认 Python 跑的是不是你刚覆盖的那个目录
  parser.py  mtime=...          <- 确认文件是新的（时间应为你覆盖文件的时刻）
collect: caret_mod=... caret=... <- caret 为 None 说明没拿到光标（会自我提示）
  mod=UserForm3 ... caret_applied=True
trigger: ... word='n' proc=... module=...
  raw hits for 'n': [...]        <- 关键字原始记录：看它属于哪个模块/过程
```

- `raw hits` 里**没有**目标变量 → 解析层没收录（看它是赋值语句还是只读用法）
- `raw hits` 里有、但 `matches` 没有 → 被作用域过滤掉了（过程/模块不匹配）
- `caret_applied=False` 或 `caret=None` → 会出现"打什么提示什么"的自我提示

**模糊匹配时代的额外排查**（v36 起，`raw hits` 已按模糊规则筛选）：

- `hit positions: {...}` 这行会列出每个候选的命中下标。**下标对不上号**就说明
  高亮位置不对 —— 但请先记住 `positions` 是**对 `name` 本身的字符下标**
  （`dataSheet` 里 `S` 是第 5 个字符，即下标 4），不是相对输入串的。
- 若某个候选**该出现却不在列表里**：看 `raw hits` 里有没有它。若在 `raw hits` 里
  却不在 `matches`，那是被"自我提示防护"剔掉了（它就是光标处那个词的回声）。
- **想让结果更"收敛"**：模糊匹配是"按顺序出现即命中"，字符越长越精确。
  多打一两个字母（`ts` → `tsh`）就能迅速收窄，这比改配置有效。
